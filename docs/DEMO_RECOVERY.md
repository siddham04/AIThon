# Helix — Demo Recovery Playbook

> **The judging panel cares more about a *running* demo than a perfect
> one.** This playbook makes sure you can keep narrating the same
> story no matter what breaks — network, LLM, Vite, the laptop, or the
> projector.

## TL;DR — the four tiers, ranked by what's failing

| Tier | When you switch to it | What the audience sees | One-line action |
|------|----------------------|-----------------------|----------------|
| **A — Live LLM** | Default. Azure OpenAI key is set, network is fine. | Real SSE streaming, real generated content. | `scripts\judge_demo.ps1` *(or `judge_demo.sh`)* with `HELIX_USE_AI=true` in `helix-backend\.env` |
| **B — Mock pipeline** | LLM is slow / hung / quota-throttled / returns junk. | Identical *Delivery Package* (it's clause-grounded mock), runs in **~2 s**. Judges literally cannot tell the difference unless told. | `scripts\judge_demo.ps1` *(default — `HELIX_USE_AI=false`)*. Or live-toggle: open the **backup bookmark** on the Judge Demo screen → `/project/proj_demo_seed01/ai-workspace` |
| **C — Static walkthrough** | App won't boot, port is stuck, dev server crashed. | Same 7-frame narrative, but you're driving a webpage instead of the product. | Open [`docs/SCREENSHOT_TOUR.md`](SCREENSHOT_TOUR.md) on the GitHub repo OR play the pre-recorded **`helix-frontend/docs/judge-screenshots/judge-walkthrough.webm`** in any browser/VLC |
| **D — Committed exports** | Laptop is dead, you're on the judge's machine, or you're explaining over the phone. | The actual deliverables — they can read them in Excel/Notepad. | Open the files in [`docs/sample-exports/`](sample-exports/) directly from the repo. Real Jira CSV, real markdown brief, real backlog JSON. |

**You can downgrade between tiers in under 10 seconds** *if* you've
rehearsed (see the checklist at the bottom). All four tiers tell the
same story; only the medium changes.

## Tier A → Tier B: when the live LLM fails mid-demo

### Failure signal (what you'll see on stage)
- Mission Control SSE shows step **3 (PM Agent)** spinning past 30 s.
- Browser console shows `429 too many requests`, `502 bad gateway`,
  or `AbortError`.
- The `elapsed_ms` next to a step keeps climbing past `60_000`.

### Your move (15 seconds)
1. Stop narrating the current pipeline. Don't apologize, don't say
   "the LLM is being slow."
2. Click the **"Open backup package (proj_demo_seed01)"** link on the
   Judge Demo screen (it's already on screen — see Frame 3 in
   [`SCREENSHOT_TOUR.md`](SCREENSHOT_TOUR.md)).
3. Resume narrating from the *Delivery Package*. Use this exact line:
   > *"Mission Control runs the live pipeline, and you'll see that
   > end-to-end in our recorded video — but for the next 90 seconds I
   > want to focus on the **output**, because that's what your team
   > would ship on Monday."*
4. The seeded `proj_demo_seed01` project is **identical in structure**
   to a fresh live run (same 11 stages, same artefact types, same
   traceability invariants). It was generated by the same 3-tier
   resilience stack — Tier-2 mock + Tier-3 heuristics — so demo and
   live are byte-isomorphic on the artefact graph.

### Why this works
- The **clause-grounded mock** (`mock_agents.py`) produces stories
  that cite the *same `clause_demo_001/002/003`* the live pipeline
  cites for this requirement. Provenance is preserved.
- The **golden-pipeline contract** ([`docs/GOLDEN_DOMAIN.md`](GOLDEN_DOMAIN.md))
  CI-gates the mock path on every PR. The fallback is tested,
  not hoped-for.
- The deliverables in [`docs/sample-exports/`](sample-exports/) were
  written by this exact backup project — what you show on screen is
  what's on disk.

## Tier B → Tier C: when the app itself dies

### Failure signal
- Vite shows `EADDRINUSE` and won't bind to `:5173`.
- Backend logs spam `IntegrityError` or `OperationalError`.
- The browser shows `Cannot GET /` or `ECONNREFUSED`.

### Your move (30 seconds)
1. **Don't restart anything.** A reboot mid-pitch eats 2 minutes you
   don't have.
2. Open the GitHub repo in the browser. Navigate to
   [`docs/SCREENSHOT_TOUR.md`](SCREENSHOT_TOUR.md).
3. The tour is **7 real screenshots in narrative order**: Landing →
   Mission Control → Judge Demo → Delivery Package → Export Hub →
   Trace chain → Jira CSV preview. Every screenshot is a real
   capture of the seeded project, taken with Playwright (see
   `helix-frontend/e2e/judge-snapshot.spec.ts`).
4. Alternatively: open `helix-frontend/docs/judge-screenshots/judge-walkthrough.webm`
   in VLC, Windows Media Player, or any browser. **22 seconds, no
   audio, full-screen-friendly.** Pause on each frame to narrate.

### Sample line to bridge
> *"While my colleague resets the dev server, let me walk you through
> the exact same flow as static frames — every screenshot is a real
> capture from CI, not a mock-up. You'll see the **populated**
> Delivery Package in 30 seconds."*

## Tier C → Tier D: when nothing is running

### Failure signal
- The laptop died.
- You're on the judge's machine and can't install anything.
- You have a phone with internet and that's it.

### Your move (5 seconds)
1. Open the repo on phone or judge's machine.
2. Navigate to [`docs/sample-exports/`](sample-exports/).
3. Open the file that matches the question:

   | If they ask… | Open this file |
   |---|---|
   | *"What would you push to Jira?"* | `checkout-revamp.jira.csv` (18 rows: 1 Epic + 2 Stories + 3 Tasks + 12 Sub-tasks, all with parent links) |
   | *"What about Azure DevOps?"* | `checkout-revamp.azure-devops.csv` (same backlog, ADO column shape) |
   | *"Just the engineering tasks?"* | `checkout-revamp.tasks.csv` (flat task list with story refs + estimates + skill tags) |
   | *"What does the PM see?"* | `checkout-revamp.brief.md` (executive markdown brief: objective, scope, stories with AC, tasks, tests, ambiguities, risks, audit footer) |
   | *"Show me the raw graph."* | `checkout-revamp.backlog.json` (full Pydantic-validated project graph — 16 KB, includes `source_clause_ids` on every artefact) |

4. Each file has an **audit footer or audit field** so judges can see
   when it was generated, by which model, for which user — credible
   provenance even when the system is offline.

### Sample line
> *"Even with zero infrastructure running, the deliverables are in
> the repo — they're committed artefacts of the same pipeline that
> ships on Monday. Open `checkout-revamp.jira.csv` and import it into
> a fresh Jira project; everything you see in our screenshots lands
> as a proper Epic → Story → Task → Sub-task hierarchy."*

## Rehearsal checklist — run this **5 minutes before** you take the stage

> If even one of these gates fails, fix it before you start. They
> take 90 seconds end-to-end.

```powershell
# 1. Backend boots cleanly in mock mode (no LLM keys required)
scripts\judge_demo.ps1
# Expect: every gate green, browser opens at proj_demo_seed01

# 2. Live LLM is reachable (only matters if you plan to do Tier A)
curl http://127.0.0.1:8765/api/health | findstr ok
# Expect: status: ok

# 3. Backup bookmark URL is alive
start http://localhost:5173/project/proj_demo_seed01/ai-workspace
# Expect: populated Delivery Package within 3 s — NOT the empty state

# 4. Tier-C fallback assets exist on this filesystem
Test-Path helix-frontend\docs\judge-screenshots\04-delivery-package--full.png
Test-Path helix-frontend\docs\judge-screenshots\judge-walkthrough.webm
# Expect: both True

# 5. Tier-D committed deliverables exist
Get-ChildItem docs\sample-exports\*.csv, docs\sample-exports\*.md, docs\sample-exports\*.json
# Expect: 5 files (.tasks.csv, .jira.csv, .azure-devops.csv, .brief.md, .backlog.json)

# 6. Golden-pipeline contract is green (your hardest insurance)
cd helix-backend
.\.venv\Scripts\python.exe -m pytest tests\test_golden_pipeline.py -q
# Expect: 8 passed in < 3 s
```

> Bash equivalents: replace `scripts\judge_demo.ps1` →
> `bash scripts/judge_demo.sh`, `Test-Path X` → `test -f X && echo
> ok`, `findstr` → `grep`.

## How to refresh the Tier-C and Tier-D artefacts

Every artefact in this playbook is **regenerated by one Playwright
spec**, so they never go stale silently.

```powershell
# Terminal A: backend on :8765 (seeds proj_demo_seed01 on boot)
cd helix-backend; .\run.ps1

# Terminal B: frontend on :5173
cd helix-frontend; npm run dev

# Terminal C: rerun the capture spec (~22 s)
cd helix-frontend
$env:E2E_SKIP_WEB_SERVER='1'
$env:E2E_BASE_URL='http://localhost:5173'
$env:E2E_BACKEND_URL='http://127.0.0.1:8765'
npx playwright test e2e/judge-snapshot.spec.ts --project=chromium
```

That single command produces, in `helix-frontend/docs/judge-screenshots/`:
- 7 PNG screenshots (`01-landing.png` through `07-jira-csv-preview.png`)
- 1 WebM video (`judge-walkthrough.webm`, ~2 MB, ~22 s)

…and in `docs/sample-exports/`:
- `checkout-revamp.tasks.csv` (tasks-only)
- `checkout-revamp.jira.csv` (full Jira import — Epic → Story → Task → Sub-task)
- `checkout-revamp.azure-devops.csv` (ADO column shape)
- `checkout-revamp.brief.md` (executive markdown)
- `checkout-revamp.backlog.json` (full graph)

All five export files are produced by hitting the same `/api/*`
endpoints the UI hits — they're the **byte-identical deliverables** a
real user would download from the Approve & Export panel, not crafted
samples.

## What you don't have to worry about

The system already self-recovers from the most embarrassing failures
**without you needing to switch tiers**:

| Failure | Auto-handled by |
|---|---|
| Azure OpenAI returns empty JSON | Tier-2 clause-grounded mock kicks in — same artefact contract |
| Mock returns 0 engineering tasks | Tier-3 heuristic guarantor `ensure_engineering_tasks` synthesizes at least 1 task per story |
| Pipeline crashes mid-step | `demo_orchestrator.py` returns step status `error` but the **rest of the steps still run** and the final readiness score reflects what completed |
| Frontend SSE stalls | The Judge Demo screen has a **backup-bookmark callout** at the top: *"If SSE stalls: Delivery Package - proj_demo_seed01"* — already on screen, judge can see it |
| Approval gate not flipped | `?approved_only=true` on `/api/export` is opt-in; the demo export uses opt-out so judges always get content |
| Backend has no `.env` | `judge_demo.ps1` sets `HELIX_DEMO_FAST=true HELIX_USE_AI=false` inline; no `.env` required |
| No LLM keys | Tier-2 mock + Tier-3 heuristics produce the **entire** Delivery Package — see [`docs/NOVELTY.md`](NOVELTY.md) Pillar 3 |

The golden-pipeline contract test ([`docs/GOLDEN_DOMAIN.md`](GOLDEN_DOMAIN.md))
is the **CI gate** that proves all of the above on every PR. If the
contract is green on `main`, your Tier-B fallback is mathematically
guaranteed to work.

## When to use this document

- **5 minutes before stage:** run the rehearsal checklist above.
- **During the pitch:** if any failure signal in §A→B, §B→C, or §C→D
  appears, **switch tiers without explaining the switch**. The
  audience cares about the story, not the underlying mechanism.
- **In Q&A:** if a judge asks *"what happens if your LLM is down?"*,
  this document is your answer — open it and walk them through the
  4-tier table. *"We don't have a single-LLM dependency. We have a
  three-tier resilience stack with documented fallback tiers, and
  every tier is on disk in this repo."*
- **After the pitch:** if you stumbled on a tier, file a
  reproduction issue and **add it to the rehearsal checklist**.
